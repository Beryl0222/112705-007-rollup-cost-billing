# 输入协议

文件为 UTF-8 JSONL。每行包含 `seq`、`observed`、`kind`、`payload`。序号从 1 连续递增，观察秒单调不降。同秒资料的观察次序由序号确定。记录内明确给出的业务生效秒可早于观察秒。文件间实体空间相互独立。

同一报价号是租户在一段有效期内的总预算，消耗按二层交易序列归属并独立于付款日期。参与计算的交易在受理时必须带可用报价，作业继续处理后来提交的回执时使用原承诺。账单可包含同一结算权属下的多个报价。
发布器按总记账字节和共享字节合计标注批次间的权重；对于已可分摊的批次，批内按交易所申报的记账字节分摊。以费用币种最小单位向下结算，共享权重的尾差、归不到交易的金额以及超出报价的部分归运营。实际费用由一层记录认定；链不认可的块不贡献当前真实支出。关闭数据可用标志不会移除仍存在的一层真实支出。

## 记录类型

### `quote`

- `id`（字符串）为报价号。
- `tenant`（字符串）为机构。
- `account`（字符串）为结算权属。
- `currency`（字符串）为费用币种。
- `cap`（整数）为报价总上限最小单位。
- `until`（整数）为承诺截止秒。

### `tx`

- `id`（字符串）为二层交易号。
- `sequence`（整数）为二层序列。
- `quote`（字符串）为报价号。

### `batch`

- `id`（字符串）为发布批号。
- `segments`（数组）为交易号与记账字节数二元组。
- `overhead`（整数）为共享字节数。

### `attempt`

- `id`（字符串）为一层交易号。
- `batches`（数组）为各发布批号。

### `gas`

- `attempt`（字符串）为一层交易号。
- `block`（字符串）为所在块。
- `amount`（整数）为真实成本最小单位。

### `chain`

- `block`（字符串）为所在块。
- `canonical`（布尔值）为当前认可的一层块。

### `accept`

- `batch`（字符串）为批号。
- `attempt`（字符串）为一层交易号。
- `available`（布尔值）为数据已可用。

### `bill`

- `id`（字符串）为账单号。
- `account`（字符串）为结算权属。
- `txs`（数组）为交易号集合。

### `paid`

- `id`（字符串）为收款回报号。
- `bill`（字符串）为账单号。
- `amount`（整数）为实际付款最小单位。
